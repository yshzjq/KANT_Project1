## STEP 1. 문제 정의

> **Slack API를 통해 수집한 교육 데이터를 기반으로 사용자의 한국어 질문에 정확하고 근거 있게 답변할 수 있는 로컬 LLM 기반 Q&A Assistant에 적합한 모델을 선정한다.**

### 어떤 사용자가 사용하는가?

* LLM 교육 과정에 참여하는 교육생이 사용한다.
* 사용자는 교육 일정, 시험, 과제, 학습 방법, 운영 안내 등 Slack에 공유된 정보를 질문한다.
* 사용자는 원하는 정보를 직접 여러 Slack 메시지에서 찾아보는 대신, 자연어 질문을 통해 필요한 내용을 빠르게 확인할 수 있어야 한다.

### 어떤 종류의 질문에 답해야 하는가?

* Slack에 저장된 교육 관련 정보를 바탕으로 질문에 답해야 한다.
* 하나의 메시지만으로 답할 수 있는 단순 정보 검색뿐 아니라 여러 메시지의 내용을 종합해야 하는 질문에도 대응해야 한다.
* 질문과 Slack 원문의 표현이 다르더라도 의미적으로 관련된 내용을 찾아 활용할 수 있어야 한다.
* 현재 일정, 개인 배정, 제출 여부 등 근거가 없는 정보는 임의로 추측하지 않아야 한다.
* 자료에서 확인할 수 없는 내용은 정보를 생성하지 않고 확인할 수 없음을 명확하게 안내해야 한다.

### 어떤 성능이 중요한가?

* **한국어 질문 이해 및 답변 품질**
  사용자의 질문 의도를 정확하게 이해하고, 핵심 정보를 빠뜨리지 않으면서 자연스러운 한국어로 답변해야 한다.

* **검색어 생성 품질**
  사용자의 질문에서 Slack 검색에 필요한 핵심 키워드를 정확하게 추출하고, 불필요하거나 질문과 관계없는 검색어를 과도하게 생성하지 않아야 한다.

* **관련 문맥 검색 능력**
  생성된 검색어를 이용해 질문에 답하는 데 필요한 Slack 메시지를 적절하게 찾을 수 있어야 한다.

* **근거 기반 답변**
  검색된 Slack 기록에 실제로 존재하는 내용을 근거로 답변해야 한다.

* **Hallucination 억제**
  자료에 존재하지 않는 인물, 일정, 링크, 규칙, 개인 상태 등을 임의로 생성하지 않아야 한다.

* **정보 부족 시 대응**
  필요한 근거가 없을 경우 추측하지 않고 현재 자료만으로는 확인할 수 없음을 적절하게 안내해야 한다.

* **응답 속도**
  실제 Q&A Assistant로 사용할 수 있을 정도의 응답 시간을 확보해야 한다.

### 모델을 어떤 기준으로 비교하는가?

* 모든 후보 모델에 동일한 질문 세트와 동일한 Prompt를 사용한다.
* 모델이 생성한 검색어와 실제 검색에 사용된 검색어를 비교하여 검색어 생성 품질을 평가한다.
* 검색된 Slack 문맥에 필요한 근거가 포함되었는지 확인한다.
* 최종 답변은 다음 항목을 기준으로 평가한다.

  * 정확성
  * 핵심 정보 포함 여부
  * 지시 및 형식 준수
  * 한국어 표현
  * 정보 부족 시 대응
* 검색 단계와 최종 답변 생성 단계를 분리하여 오류 원인을 분석한다.

  * 관련 자료를 찾지 못한 경우: **검색 실패**
  * 관련 자료가 제공되었지만 잘못 답한 경우: **근거 해석 또는 답변 생성 실패**
* 답변 품질뿐 아니라 **응답 시간, 모델 로딩 시간, 생성 속도(tokens/s), VRAM 사용량, CPU/GPU 적재 상태** 등의 실행 성능도 함께 측정한다.
* 답변 품질과 실행 성능 사이의 균형을 고려하여 최종 모델을 선정한다.

### 사용 가능한 실행 환경은 어느 정도인가?

* 로컬 PC에서 Ollama를 통해 실행 가능한 모델을 주요 비교 대상으로 한다.
* GPU VRAM과 시스템 메모리 한계를 고려하여 모델 크기와 양자화 여부를 함께 검토한다.
* GPU에 전체 모델이 적재되는 경우와 CPU/GPU에 나누어 적재되는 경우를 구분하여 성능을 해석한다.
* 후보 모델이 동일한 로컬 실행 환경에서 안정적으로 동작하는지 확인한다.
* Qwen3, EXAONE, Gemma 3, Llama 3.1, Phi-4 mini 등 서로 다른 계열과 크기의 모델을 비교하여 프로젝트에 적합한 모델을 선정한다.
